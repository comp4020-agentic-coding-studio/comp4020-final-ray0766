The investigation separated observable findings from an unproven historical machine cause:

- A native Node 24.21.0 CPU profile of two generated homes showed repeated terrain noise, support and collision work. The same `move` candidate and support ceiling were queried twice, first in `move` and immediately again in `radial`. The latter now reuses the exact computed result. A new regression compares 90 frames each of walking, falling and wall sliding against the former recomputing path, with strict equality of the entire pose, collision checks and a measured reduction in support calls. All three passed. Seeds 0 and 1 also retain byte-identical generated-manifest SHA-256 hashes. The short timings are not a controlled cross-device performance claim.
- This eight-core Mac's installed Vitest 5 default allows seven file processes. Generating terrain/collision fixtures in those processes competes with the HTTP server and tests' preparation workers. `vitest.config.ts` now caps file concurrency at two; all app cases remain included and legacy HTTP still runs sequentially. This is a bounded scheduling policy, not a higher timeout or a claim that two workers are optimal everywhere.
- `heavy-work.test.ts` created temporary database/bundle directories without removing them. It now registers only its own directories, closes stores, awaits worker shutdown and removes those directories even when an earlier cleanup fails. Cleanup errors are reported rather than swallowed. No old temporary directory or player data was swept. This was a real fixture lifecycle defect, but was not proved to cause the old CPU timeouts.
- Before the code optimization, the formerly failing indoor-actions case passed unchanged in 1.331s; the unchanged eleven-seed generation setup plus one selected case completed in 7.13s. This demonstrates substantial variation from the earlier 7.9–9.8s indoor failure and 30s generation hook failure. The exact prior system contention/thermal/I/O cause cannot be recovered from the old logs; it is not honestly attributable to one process. The current repairs are supported by profiling and exact-equivalence tests, and the full gate now passes rather than relying on that attribution alone.
