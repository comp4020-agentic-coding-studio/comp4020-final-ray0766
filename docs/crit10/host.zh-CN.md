# 主持人清单（不发给参与者）

## 开始前

1. 明确本次是本地准备性演练还是已部署 Crit10；填写[记录模板](observation-template.zh-CN.md)的版本、URL、时区和开始时间。线上新日志尚待批准部署，本地结果不能代替线上结果。只在[规范目录](../../MIDPOINT.md)工作，不重建或替换真实库。
2. 约两位同学各用独立 Chrome profile，不共享 cookies/storage；两个同一 Chrome 的无痕窗口可能共享身份，不按窗口数当人数。保留各自身份，不让他们清除存储来重试。
3. 在应用外说明观察用途、只保留化名事件，征得记录/截图意愿。将人名与P1/P2的对应只留在作者私有笔记；不记录账号、cookie或屏幕上的私人通知。
4. 准备终端[日志视图](logs.zh-CN.md)，记UTC时间，只读 `/healthz` 确认目标可达；不调用 `/api/state` 做探针，否则会创建身份。不要预先打开他们的应用或替他们改状态。
5. 只把确认可达的 URL 发给同学，不发本清单、权限矩阵、攻略或任务卡。预先检查只属于作者环境的准备步骤，不计作同学完成。

## URL-only 阶段

- 两人并排使用，自己决定做什么；作者不点自己的UI、不接管键鼠、不代输API，也不口述“先去哪再按什么”。同学卡住时记下页面和等待结果，不用提示路线救场。若必须帮助，记录原话及时间，帮助后的片段另标“已提示”，不能补写成URL-only通过。
- 作者只据终端事件说明：某个 `visitor-…` 在何时发起什么动作、服务器接受/拒绝/失败、涉及哪个技术目标。别名不含真人身份；先各自首次进入的时间窗口可帮助对应P1/P2，交错不清就保留未知，不猜。
- 看两人是否自然遇到共享状态，以及一方的改变是否无需另一方刷新就出现。没有相遇或共享变化则记“未观察到”，不靠作者点击补成成功。外门可由近处访客操作，房间进入/编辑和历史仍受所有权限制；参见[矩阵](permissions.zh-CN.md)。
- 日志中的 accepted 不自动等于发生持久改动：预览、读取和幂等重试也会accepted。只据日志不能证明帧率、具体坐标、家具内容、整页可用性或跨会话持久性。

## 收尾

记结束UTC时间，保存实际观察、作者当时解释、同学原话、未确定之处；按[导出流程](logs.zh-CN.md)保存有限时间窗。权限按钮被隐藏、未触发请求或没有日志，都不能宣称服务端拒绝已经真人验证。必要的定向API/权限复查只能在URL-only阶段之后另立记录、隔离数据并经授权进行，不属于本清单自动安排的动作。

记录结果是“观察到了什么／没看到什么／出现什么故障”，不是预先勾选通过。演练后由学生本人写 `reflections/crit-10.md`；不把本准备文档当反思，不为完成清单伪造真人证据。
